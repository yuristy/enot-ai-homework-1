# Состояние проекта

> Обновляется в конце каждой сессии. Описывает «как есть сейчас», а не историю
> изменений — старое перезаписывается. Первым делом в новой сессии агент читает
> именно этот файл.

**Обновлено:** 2026-08-17, сессия 2

## Готово

- Контекст (`AGENTS.md` Часть II) и `SPEC.md` — заполнены, приняты.
- Снапшот данных `src/data/events-snapshot.json` — 18 мероприятий Москвы,
  17–31 августа 2026, реальный источник (KudaGo).
- Наивный прогон — ветка `naive-run`, изолирован, не трогать/не сливать
  без отдельного решения (нужен для итогового сравнения в README).
- Рабочий экран по спеке на `main`: карта (React + react-leaflet + Leaflet),
  календарь (свой, без библиотеки), фильтр по категории, три состояния,
  сохранение фильтра в `localStorage` с валидацией, карточка мероприятия
  с закрытием по `Esc`.
- Дизайн-проход (сессия 2, скилл `frontend-design`): визуальная переработка
  вокруг метафоры московского метро/табло отправления — цветные
  категории-чипы вместо `<select>`, моноширинный шрифт для дат/времени,
  карточка мероприятия в виде билета с перфорацией, тёмно-синяя палитра с
  янтарным акцентом (+ светлая тема). Никаких новых зависимостей не
  добавлено (только системные шрифты). Скриншоты «до/после» —
  `sessions/screenshots/before/` и `sessions/screenshots/after/`.
- Попутно найден и исправлен реальный баг мобильной вёрстки: на 360px список
  мероприятий был сжат flex-раскладкой до 17px (невидим) из-за конкуренции
  за жёсткую `100dvh`. Мобильная раскладка переведена на обычный скролл
  страницы вместо жёсткого деления viewport — баг устранён.
- Проверено вживую в браузере (claude-in-chrome) после дизайн-прохода: все
  три состояния на 1440 и 360px (приём с `<iframe>` для честной мобильной
  ширины), клавиатурная навигация (`Tab`/`Enter`/`Esc`, видимый фокус),
  испорченный `localStorage`, консоль без ошибок. Светлая тема проверена
  приближённо (подмена CSS-переменных вручную) — не через реальный
  `prefers-color-scheme`, см. известные проблемы.
- `npm run build` и `npm run lint` — чисто (после сессии 1 и после сессии 2).

React 19.2.8, Vite 8.2.0, TypeScript 6.0.2, oxlint, react-leaflet 5.0.0 +
leaflet 1.9.4, claude-in-chrome (для проверки, не зависимость проекта),
скилл `frontend-design` (`.claude/skills/frontend-design/`, тоже не
зависимость проекта — инструмент ассистента). Подробности и обоснования —
`sessions/TOOLS.md`.

## Известные проблемы

- `README.md` в корне вводит в заблуждение — это ещё курсовой текст, а не
  инструкция по проекту. Кто угодно, кто попытается запустить проект по
  README прямо сейчас, не найдёт там `npm install`/`npm run dev`.
- Ветка `naive-run` не запушена — существует только локально.
- Марker-иконки на карте — `divIcon` с эмодзи, не проверялись на реальном
  устройстве с другим набором шрифтов/эмодзи-рендерингом (только Chrome
  desktop).
- Светлая тема (`prefers-color-scheme: light`) не проверена через реальное
  переключение системной темы — только приближённо, подменой CSS-переменных
  вручную в живой странице. Структура медиа-запроса не менялась с сессии 1
  (только значения токенов), риск низкий, но не подтверждено визуально
  через настоящий медиа-запрос.
