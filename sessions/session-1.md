## Размышления

Задачу выбирали из семи предложенных — пользователь сразу предложил свою тему
(карта мероприятий Москвы) вместо готовых вариантов из `homework.pdf`, что
допустимо и даже предпочтительно по правилам задания.

Неоднозначность №1: слово «карта» — географическая карта или каталог карточек?
Не стал гадать, спросил явно — оказалось буквальная карта, это меняет весь
стек (нужна картографическая библиотека).

Неоднозначность №2: источник данных о мероприятиях. Предложил пользователю
выбор между мок-датасетом, снапшотом с реального источника и живым API.
Выбран снапшот с реального источника — тогда нужно было найти рабочий
открытый API. Проверил через `WebFetch` `kudago.com/public-api/v1.4/events/`
до того, как предлагать его пользователю — источник действительно отвечает
без ключа и отдаёт координаты места (`place.coords`), что критично для
географической карты. Не поверил на слово описанию в интернете, проверил
фактическим запросом.

Стек менялся дважды за сессию: сначала предполагался список
HTML/JS-фреймворков, пользователь выбрал React, затем уточнил версию
(React 19). Из-за этого пришлось пересмотреть более раннее решение про
подключение Leaflet — я предлагал CDN-скрипт до того, как узнал про React,
а с бандлером логичнее npm-пакет. Спросил повторно вместо того, чтобы молча
оставить более раннее решение — правило «расхождение — повод спросить»
сработало здесь на собственном черновике, а не только на коде агента.

Отдельно был случай, когда я вызвал `AskUserQuestion` с 4 вопросами сразу
(включая multiSelect про границы задачи) — пользователь отклонил вызов
инструмента и ответил одним словом «React» в чате. Это подтверждает пункт
правил «независимый взгляд»/контроль на практике: даже безобидный вызов
инструмента может быть отклонён, и агент обязан продолжить с тем, что дал
пользователь, а не повторять то же самое.

Процессная ошибка с моей стороны: я отредактировал `SPEC.md` и `AGENTS.md`
до создания файла сессии, хотя сам же зафиксировал в `AGENTS.md`
(унаследовано из Части I) правило «создать файл сессии до первой правки
кода». Обнаружил и исправил в начале следующего шага, зафиксировано здесь

## Промпт 12 — снапшот: как делался

Промпт «Создай снапшот до 31 августа» был выполнен так:

1. Посчитал unix-диапазон 17–31 августа 2026 по московскому времени —
   без него `actual_since`/`actual_until` пришлось бы подбирать на глаз.
2. Запросил у KudaGo 100 событий с координатами, ограниченных этим диапазоном
   и Москвой (`location=msk`). Всего под фильтр подошло 412 — по протоколу
   курса не гонюсь за «настоящим» полным списком, беру рабочую выборку.
3. Отфильтровал по наличию `place.coords` (без них нечем поставить метку на
   карте — из 100 таких оказалось 74) и по «развлекательным» категориям
   (исключил `education`, `business-events`, `stock`, `other` — тема экрана
   именно развлечения, не образование/бизнес).
4. У KudaGo многие события — повторяющиеся (одно и то же мероприятие с
   десятками дат, включая записи аж с 2015 года и вплоть до плейсхолдерной
   даты `0001-01-03`). Для снапшота это усложнение не нужно: для каждого
   события взял только одно вхождение даты, которое попадает в окно
   17–31 августа 2026 — самое раннее из подходящих. Реального расписания
   повторов снапшот не хранит, это явное упрощение, записано в `meta.note`
   самого файла снапшота.
5. Вручную отобрал 18 из 47 отфильтрованных кандидатов, добиваясь разброса
   по категориям (7 категорий) и по дням (8 разных дней из 15 в диапазоне) —
   так, чтобы часть комбинаций «день + категория» осталась пустой без
   искусственной подгонки: это нужно для честной проверки состояния
   «Ничего не найдено» из `SPEC.md`.
6. Сырой ответ API (100 событий) и промежуточный список кандидатов (47) не
   стал класть в репозиторий — это дамп и черновик, а не часть сдачи;
   сохранены только в скретчпад-директории сессии инструмента.

Отдельно отмечу: снапшот не проверялся визуально на самой карте — карты
как таковой ещё нет, реализация не начата. То, что все 18 точек физически
попадают в Москву и координаты не искажены, будет видно только на этапе
реализации; если окажется, что какая-то метка вылезла за пределы города —
это и будет тем самым «расхождение — повод спросить», а не тихая правка.

факт, что повторная проверка находит новое, означает, что и следующая может
найти ещё — сейчас файлы закрывают всё, что явно требует курс для
Frontend-задания, но stress-test — это наивный/spec-прогон, а не чтение
текста.

Обнаружен пробел вне контента файлов: **папка не является git-репозиторием**
(`git status` → `fatal: not a git repository`). Для сдачи нужен репозиторий с
историей коммитов, а для наивного прогона по правилам курса — «ветка, папка
или коммит с первым результатом», то есть результат наивного прогона должен
физически не смешиваться с версией по спеке. Без git самый естественный
вариант — раздельные папки; с git — отдельная ветка или ранний коммит. Это
нужно решить до того, как запускать наивный прогон, а не после.
