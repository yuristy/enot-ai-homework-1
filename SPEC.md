# Спецификация

## Что делаем

Веб-экран с географической картой Москвы, на которой показаны развлекательные
мероприятия (концерты, фестивали, выставки и т.п.) с фильтром по дате (календарь,
выбор одного дня) и категории.

## Для кого и зачем

Житель или гость Москвы, который хочет быстро увидеть, какие мероприятия проходят
в конкретный день и где именно — не читая длинные афиши, а глядя на карту.

## Сценарии

1. Открыть страницу → карта показывает мероприятия по умолчанию (ближайшие 7 дней
   от даты снапшота, все категории), день в календаре не выбран.
2. Выбрать день в календаре → карта обновляется, показывает только мероприятия
   этого дня; выбранный день подсвечен в календаре.
3. Выбрать категорию (кроме «все») → список меток на карте дополнительно
   фильтруется по категории.
4. Кликнуть на метку → всплывает карточка с деталями: название, время, место,
   категория.
5. Выбрать день + категорию, для которых нет мероприятий → карта показывает
   состояние «ничего не найдено».
6. Перезагрузить страницу → последний выбранный фильтр (день + категория)
   восстанавливается из `localStorage`. Если сохранённые данные испорчены или
   принадлежат чужому формату — экран не падает, а сбрасывается в состояние
   «Пусто».

## Состояния

- **Пусто (первый заход).** День в календаре не выбран. Карта показывает
  мероприятия за дефолтный период — ближайшие 7 дней от даты снапшота, без
  фильтра по категории.
- **Есть данные.** Пользователь явно выбрал день (и опционально категорию), для
  которых нашлось хотя бы одно мероприятие. Карта показывает только их,
  календарь подсвечивает выбранный день.
- **Ничего не найдено.** Выбранная комбинация дня и категории не даёт ни одного
  мероприятия. Карта пустая, показывается сообщение и подсказка сменить фильтр.

## Чего точно не делаем

- Авторизация и личный кабинет — никаких пользователей, входа, избранного на
  сервере.
- Создание и редактирование мероприятий — экран только читает и показывает
  данные снапшота.
- Построение маршрута и геолокация пользователя — никакого «как добраться»,
  определения текущего местоположения.
- Живые запросы к KudaGo в рантайме — работаем со статичным снапшотом в
  репозитории, а не с сетевым API при каждом открытии страницы.

## Допущения

- **Источник данных — статичный снапшот KudaGo, а не живой API.** Так сдача
  воспроизводима и не зависит от сети и лимитов стороннего сервиса во время
  проверки. Снапшот — 15–20 мероприятий, дата обращения зафиксирована в файле.
- **Дефолтный период состояния «Пусто» — 7 дней от даты снапшота.** Число нужно
  зафиксировать, чтобы состояние было воспроизводимо и проверяемо, а не
  «недавние» на глаз.
- **Категории — только те, что реально есть среди отобранных 15–20 событий
  снапшота**, а не полный список категорий KudaGo — иначе часть фильтров будет
  вести в пустоту не по сценарию, а из-за пустой выборки.
- **Карта — Leaflet + `react-leaflet`, тайлы OpenStreetMap**, подключены как
  npm-зависимости (не CDN-скрипт), так как в проекте уже есть сборщик (Vite) под
  React 19.
- **Стек — React 19 + TypeScript + Vite.** TypeScript строже к данным снапшота и
  координатам, ошибка формы данных ловится на этапе сборки, а не в рантайме на
  карте.
- **Снапшот подключается статическим импортом JSON в бандл, а не через
  `fetch`/`public/`.** На чистой машине проверяющего при первом запуске не
  будет сетевых обращений и связанных с сетью сбоев — данные уже внутри
  собранного приложения.
- **Доступ к данным мероприятий — через один модуль-загрузчик со своим типом
  `Event`, а не напрямую из компонентов.** Сегодня модуль читает снапшот;
  переход на живой KudaGo API в будущем — это правка одного файла (заменить
  чтение JSON на `fetch` + маппинг в тот же тип `Event`), компоненты и карта
  формат KudaGo вообще не видят и не меняются.

## Открытые вопросы

Вопросы, заданные агентом в ходе обсуждения спецификации, и ответы:

- **Буквальная карта или список карточек?** → Буквальная географическая карта.
- **Источник данных о мероприятиях?** → Снапшот с реального открытого источника;
  выбран KudaGo API (`kudago.com/public-api`, проверено 15.08.2026: отвечает
  без ключа, отдаёт координаты места).
- **Критерии фильтра?** → Категория + дата.
- **Роль календаря?** → Выбор одного дня.
- **Стек?** → React 19 + Vite + TypeScript.
- **Как подключать Leaflet?** → npm-пакетами `leaflet` и `react-leaflet`, не
  CDN — раз в проекте уже есть сборщик.
- **Определение трёх состояний?** → см. раздел «Состояния» выше, согласовано
  без изменений.
- **Границы задачи?** → согласован список раздела «Чего точно не делаем» без
  изменений.

## Критерии приёмки

- [ ] Все три состояния («Пусто», «Есть данные», «Ничего не найдено») достижимы
      руками из интерфейса, без правки кода.
- [ ] Экран корректно работает на ширинах 360 и 1440 px: нет горизонтальной
      прокрутки, ничего не обрезано, интерактивные элементы не перекрывают друг
      друга.
- [ ] Клик по метке на карте открывает карточку мероприятия с данными из
      снапшота (название, время, место, категория).
- [ ] Комбинация «день + категория» корректно фильтрует метки, включая случай,
      когда результат пуст.
- [ ] Последний использованный фильтр восстанавливается после перезагрузки
      страницы через `localStorage`; испорченные данные в `localStorage` не
      ломают экран, а сбрасывают его в состояние «Пусто».
- [ ] Полная клавиатурная доступность: `Tab` обходит все интерактивные
      элементы, фокус видно, `Enter`/`Space` срабатывают на них, `Esc` закрывает
      карточку мероприятия.
- [ ] Есть скриншоты «до / после» улучшения дизайна — одна ширина окна, одни и
      те же данные.
- [ ] Снапшот KudaGo (15–20 мероприятий) лежит в репозитории в виде файла,
      помечен датой обращения к API.
