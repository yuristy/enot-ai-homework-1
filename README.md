# Карта мероприятий Москвы

Веб-экран с географической картой Москвы, на которой показаны развлекательные
мероприятия (концерты, театр, кино, вечеринки, экскурсии и т.п.) с фильтром по
дате (календарь, один день) и категории. Данные — статичный снапшот KudaGo API,
без бэкенда. Полная спецификация — [`SPEC.md`](SPEC.md).

## Запуск

Требуется Node.js ≥ 20 (в разработке использовался v26.5.0) и npm.

```bash
# установка зависимостей (на чистой машине — после клонирования)
npm ci

# запуск — строго порт 5173
npm run dev -- --port 5173 --strictPort
# → http://localhost:5173

# сборка
npm run build

# линтер
npm run lint
```

Данные не грузятся по сети — снапшот `src/data/events-snapshot.json` уже лежит
в репозитории, страница работает сразу после `npm ci` + `npm run dev`.

## Три состояния экрана

- **Пусто** (первый заход, день не выбран) — карта и список показывают
  мероприятия за ближайшие 7 дней от даты снапшота, без фильтра по категории.
- **Есть данные** — выбран день (и опционально категория), для которых
  нашлось хотя бы одно мероприятие.
- **Ничего не найдено** — выбранная комбинация дня и категории не даёт ни
  одного мероприятия.

Фильтр (день + категория) сохраняется в `localStorage`; испорченные или чужие
данные в хранилище не роняют экран, а сбрасывают его в «Пусто».

## Что сделано

- Рабочий экран по [`SPEC.md`](SPEC.md): карта (React + react-leaflet +
  Leaflet), собственный календарь без библиотеки, фильтр по категории
  (цветные чипы), три состояния, восстановление фильтра из `localStorage` с
  валидацией, карточка мероприятия с закрытием по `Esc`.
- Дизайн-проход (скилл `frontend-design`, сессия 2): визуальная переработка
  вокруг метафоры московского метро / табло отправления — цветные
  категории-«линии», моноширинный шрифт для дат и времени, карточка
  мероприятия в виде билета с перфорацией. Без новых зависимостей — только
  системные шрифты. Скриншоты «до/после» — `sessions/screenshots/`.
- Независимый аудит (сессия 3, отдельный агент на Opus 5 без контекста
  предыдущих сессий): нашёл 12 расхождений со `SPEC.md`/`AGENTS.md`, включая
  два несработавших критерия приёмки — клавиатурная активация меток на карте
  и сброс некорректной даты в `localStorage`. 11 из 12 находок исправлены и
  перепроверены вживую в браузере: клавиатура (`Tab`/`Enter`/`Space`/`Esc`,
  включая метки карты и фокус-ловушку в карточке мероприятия), устойчивость к
  испорченному `localStorage` (невалидный JSON, синтаксически валидная но
  невозможная дата, бросающее исключения хранилище), контраст текста на
  цветных чипах и карточке (WCAG AA), разведение перекрывающихся меток на
  карте по экранным пикселям. Подробности — `sessions/session-3.md`.
- `npm run build` и `npm run lint` — чисто на каждой сессии.

## Что не сделано, допущения и ограничения

- **Раскладка карты на 1440px** не использует весь доступный вертикальный
  объём так хорошо, как могла бы — независимый аудит отметил это отдельно
  (найдено в сессии 3, отложено сознательно: это дизайнерское решение, а не
  баг, и сессия 3 занималась логикой/доступностью, не оформлением — по
  тому же правилу проекта, которое требует не смешивать дизайн-правки с
  правками логики в одной сессии).
- **Светлая тема** (`prefers-color-scheme: light`) проверена только
  приближённо — подменой CSS-переменных вручную в живой странице, не через
  реальное переключение системной темы: инструменты браузерной автоматизации
  в этой среде не дают эмулировать медиа-запрос.
- **Валидация снапшота на seam'е** (`src/data/events.ts`) проверена
  код-ревью и сборкой, но не живым fault-injection — портить сам файл
  снапшота нельзя по правилам проекта (нужен для сравнения «до/после»).
- **Автотесты не заведены.** Не обязательны по минимальным требованиям
  задания для фронтенда; проверка — ручная и через `claude-in-chrome`
  (см. журнал сессий).
- Marker-иконки на карте — эмодзи в `divIcon`; не проверялись на реальном
  мобильном устройстве с другим набором шрифтов (только Chrome desktop).
- Повторный независимый аудит фиксов сессии 3 не проводился — сами правки
  проверены вживую тем же агентом, что их вносил, а не свежим взглядом.

Полное текущее состояние проекта, известные проблемы и следующий шаг —
`sessions/STATE.md`.

## Сравнение наивного прогона и работы по спецификации

Наивный прогон (ветка [`naive-run`](../../tree/naive-run), не сливалась в
`main` — изолирована специально для сравнения) сделан одним промптом без
контекста, правил и спецификации: «собери веб-страницу с картой Москвы и
мероприятиями, календарём и фильтрами». Ниже — конкретные решения, которые
агент принял сам за наивным промптом, и что в каждой строке изменила
спецификация.

| Что | Наивный прогон | Работа по спеке |
|---|---|---|
| Стек | Ванильный JS, HTML, CSS, без сборки; Leaflet — `<script>` с CDN (`unpkg.com`) | React + TypeScript + Vite; Leaflet — npm-зависимость с зафиксированной версией. `SPEC.md`/`AGENTS.md` явно запрещают CDN-скрипты в обход `package.json` — наивный прогон делает ровно то, что запрещено |
| Данные | 28 придуманных мероприятий в `events.json`, без ссылки на источник и без даты выгрузки | 18 реальных мероприятий из публичного KudaGo API, с зафиксированной датой обращения в метаданных снапшота (`sessions/TOOLS.md`) |
| Категории | 8 категорий во множественном числе (`concerts`, `festivals`...), выбраны произвольно | 7 категорий, согласованных на этапе спецификации и подтверждённых реальными данными KudaGo |
| Состояние «Пусто» | Не существует как отдельное состояние: при загрузке активны все категории, список сразу показывает все 28 событий независимо от даты | Специально спроектировано: дефолтный период — 7 дней от даты снапшота, без выбранного дня — воспроизводимо и проверяемо, а не «недавние» на глаз |
| Карточка мероприятия | Нет: клик по метке просто подсвечивает строку в списке, деталей мероприятия (описание, адрес, ссылка на источник) нигде не показать | Отдельная модальная карточка с полным описанием, адресом и ссылкой на источник; `Esc` закрывает, фокус ловится внутри и возвращается на элемент-триггер после закрытия |
| Сохранение фильтра | Отсутствует полностью — `localStorage` нигде не используется, фильтр слетает при любой перезагрузке | Фильтр восстанавливается из `localStorage` при загрузке; испорченные данные (не JSON, чужой формат, синтаксически валидная но невозможная дата) не роняют экран, а сбрасывают в «Пусто» |
| Клавиатура | Ни одного обработчика клавиатуры, `tabindex` или `aria-*` атрибута во всём файле | Полный проход по `Tab`, видимый фокус, `Enter`/`Space` активируют элементы (включая метки на карте — это потребовало отдельного фикса, см. `sessions/session-3.md`), `Esc` закрывает карточку |
| Загрузка данных | `fetch("data/events.json")` — открытие файла напрямую через `file://` не работает вообще, нужен локальный сервер | Данные импортируются статически на этапе сборки — работает сразу после `npm ci`, без сервера и без сети |
| Перекрывающиеся метки на карте | Не обрабатывается — метки в одной точке визуально накладываются, нижние некликабельны | То же самое изначально было и в spec-версии (найдено независимым аудитом), но решение зафиксировано осознанно и исправлено: метки разводятся по кругу в экранных пикселях |

**Вывод.** Наивный прогон закрывает поверхностное впечатление — карта
рисуется, календарь листается, фильтры визуально работают — но проваливает
почти все нефункциональные требования задания разом: сохранение состояния,
клавиатурную доступность, устойчивость к сети (`file://`), происхождение
данных и границы зависимостей. Ни одно из этих решений не было «плохим
кодом» — агент про них просто не думал, потому что промпт их не поставил
как требования. Спецификация не столько улучшила код, сколько заставила
явно принять решения, которые наивный прогон принял по умолчанию и молча.

Обратный пример, где наивный прогон не проигрывает: количество категорий и
общий визуальный каркас (шапка, боковая колонка со списком, карта справа)
наивный прогон угадал с первого раза почти так же, как и итоговая
структура — расхождение здесь в основном косметическое, не архитектурное.

## Структура проекта

- `src/data/events.ts` — единственный модуль доступа к данным мероприятий;
  компоненты не знают формата KudaGo и не читают снапшот напрямую.
- `src/components/`, `src/hooks/`, `src/utils/` — экран, календарь, карта,
  карточка мероприятия, фильтрация, форматирование дат.
- `sessions/` — журнал работы: `STATE.md` (текущее состояние проекта),
  `TOOLS.md` (журнал инструментов), `session-1.md`…`session-3.md`,
  `screenshots/before` и `screenshots/after` (дизайн-проход).
- `SPEC.md`, `AGENTS.md`, `CLAUDE.md` — контекст и правила проекта.
